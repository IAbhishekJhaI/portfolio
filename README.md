# Portfolio

Personal site: experience, projects (software and electronics), skills, coursework, certifications, coding profiles, and a library of books, articles and YouTube playlists. Built with [Astro](https://astro.build) as a static site.

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # type-checks content, then builds to dist/
```

## Editing content (no code changes needed)

| What | Where |
|---|---|
| Name, headline, intro, email, coding-profile handles, skills | `src/data/profile.ts` (an empty handle hides that link) |
| Engineering experience / other experience | `src/content/experience/*.md` (`track: tech` or `track: other`) |
| Projects + write-ups | `src/content/projects/*.md` (`category: software \| electronics \| other`; every non-draft project gets its own pages in the notebook, ordered by `order`) |
| Books | `src/data/books.yaml` |
| Articles (written or recommended) | `src/data/articles.yaml` |
| YouTube playlists | `src/data/playlists.yaml` |
| Certifications | `src/data/certifications.yaml` (`hidden: true` keeps one off the site) |
| Relevant coursework | `src/data/coursework.yaml` |
| Resume PDF | drop it at `public/resume.pdf`; the Resume links appear automatically |
| Project images | `public/images/projects/`, then `cover: /images/projects/x.png` + `coverAlt:` in the project's frontmatter |

Every YAML file has a commented example at the top. Set `draft: true` on any experience or project file to hide it. Lists that are empty don't render, and the build fails with a clear message if an entry is malformed.

## Link-preview image
`public/og.png` is generated by `npm run og` (edit the text in `scripts/og.mjs`).

## Deploy (Vercel)
1. Push this repo to GitHub.
2. In Vercel: **Add New → Project**, import the repo. The Astro preset is detected; no settings needed.
3. Once you have the final domain, set `SITE` in `astro.config.mjs` and the `Sitemap:` line in `public/robots.txt`.
